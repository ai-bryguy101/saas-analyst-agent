# Data catalog — Brindlecove synthetic data estate

> **ALL DATA IS SYNTHETIC.** Generated by `python -m generator` (seed 42).
> Snapshot date 2026-10-31. ~221 MB, ~8,300 files, 66 source folders.

## What to review

For a second reviewer (human or model). These are the places most likely to be
wrong or to need a decision.

1. **Golden facts are fair.** Pick 3 facts in `GOLDEN_FACTS.yaml` and try to
   answer them using only the files in their `trail`. Each one should be
   answerable, and each `traps` entry should really mislead.
   `python -m generator.verify` re-derives 31 of the 52 facts, and 2 of the 4 patterns, from the raw files.
2. **Realism versus safety (decided by default, can be reversed).** Every
   email address and web domain now ends in the reserved `.example` suffix,
   phones are 555-01xx, IPs are from documentation ranges, and keys are
   `REDACTED`. Names of real software products (Outlook, Slack, Stripe,
   QuickBooks) appear only as file formats.
3. **Messiness is real, not random.** Every quirk should have a cause a real
   company would have (a migration, a vendor default, a person's habit).
   Flag any that feel arbitrary.
4. **Size (decided by default, can be reversed).** Committed raw data is
   ~221 MB with no file over 25 MB, inside GitHub's limits (100 MB per file,
   warnings from 50 MB). Nothing is generator-only yet. If the repo should
   stay small, `data/raw` can move to "generate locally" instead.
5. **Generator code.** One `render()` per source in `generator/sources/`. The
   world model in `generator/world.py` is the only source of truth; golden
   answers are computed, never typed by hand. Runs are byte-identical.
6. **Patterns are findable but not obvious.** Read `patterns` in
   `GOLDEN_FACTS.yaml`. Each should take real aggregation or a join to see,
   and its noise should make a careless reading wrong.
7. **Prompt injection (GF51).** One vendor quote hides text addressed to AI
   assistants. It is harmless (it asks for a false $0 total) and is there to
   test that the agent flags it rather than obeys it.
8. **Formats not included.** Outlook `.msg` (OLE compound files) and
   password-protected PDFs are left out because they cannot be written
   byte-identically with the pinned libraries.

## How the estate fits together

One world model (customers, contracts, invoices, people, incidents) is
rendered through 66 source folders. Each system shows only the slice it
would have held, in its own format, with its own era's bugs. No file is
complete on its own and some files contradict each other on purpose. The
company story is in `docs/COMPANY_BIBLE.md`.

## Golden facts

`GOLDEN_FACTS.yaml` holds 52 questions (easy to hard), each with the answer,
the trail of files that prove it, the traps on the way, and machine-checkable
values. Round 1 (GF01–GF15) covers buried email, scanned documents, migration
errors, conflicting numbers, units, timezones, codenames, drafts, XML, binary
legacy, entity resolution, soft deletes, dirty categories and event logs.
Round 2 (GF16–GF38) adds: Slack approvals by deleted users, UK vs US dates,
deals agreed by text message, voicemail-only notices, faxed POs, whiteboard
photos, calendar recurrence, vCards, print reports, Lotus files, hidden
sheets, compressed diagrams, Parquet, Avro CDC, protobuf audit logs, Windows
events, web logs, ads and survey exports, QuickBooks IIF, vendor PDFs, a zip
inside a zip, and an HL7 feed.
Round 3 (GF39–GF52) is about traps: a headcount that counts contractors,
day-first dates, the 1904 date system, mixed encodings in one file,
duplicate payments under near-duplicate vendors, a truncated and
overlapping export, OCR digit confusion, schema drift, mixed epoch units,
German number formats, three "FINAL" files, sentinel dates, a hidden prompt
injection, and formulas with no saved values.

## Patterns

The same file also lists 4 planted patterns. Each is a tendency spread
across several sources with noise around it, not a single answer:

- **P01 churn driver.** Customers hit by QuickBooks connector v2 sync
  failures churn about 4 times as often. Evidence is in tickets, usage,
  check-in calls, a CSM's texts and the changelog, while CRM churn reasons
  mostly blame something else.
- **P02 seasonal and regional.** Southern facilities, property and
  hospitality customers run about 1.7 times as many work orders in summer.
- **P03 release and complaints.** Mobile 5.0 removed the offline photo
  queue. Offline tickets jumped and store ratings fell until 5.0.3.
- **P04 hidden join.** Customers whose admin finished training in the first
  30 days churn far less. The LMS export only has emails.
